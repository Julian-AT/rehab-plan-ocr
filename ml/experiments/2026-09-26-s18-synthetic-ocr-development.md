# Pixel-verified synthetic-table OCR adaptation

The frozen-backbone experiment completes four epochs (1,024 optimizer steps) and
selects epoch one after three non-improving validation epochs. Its 91/91 exact
development crops improve the pretrained 90/91 by one whitespace difference in a
therapist line. The selected checkpoint adds no newly wrong critical validation
crop. This is not evidence of real-photo or complete-schedule improvement.

The prepared dataset has 512 training crops from 129 source groups and 91 validation
crops from 42 groups, all generated by the same table generator/font. Whole source
groups were assigned before crop selection; 2,435 validation crop occurrences with
identical training pixels were excluded. Validation retains 56 dates, 26 endings,
three starts and six therapist lines. It contains no novel title, room or notes
pixels and no real photographs. Dataset SHA-256:
`7314061c5104738dea1da2f627fea27fa30612372c4402968bfe700cce073ef6`.

The official Paddle export and ONNX conversion finish. On ONNX Runtime 1.22.0 CPU,
all 603 crops at widths 320 and 640 retain the same argmax sequence (1,206/1,206),
but only 1,188/1,206 satisfy rtol 1e-3 / atol 1e-5. Maximum absolute output difference
is 0.00047653913497924805. Numerical parity therefore fails; the newly trained
artifact is not allowed into the app probe or promoted to the runtime.

Disabling ORT graph optimization on the same 18 failed cases does not fix them:
0/18 numeric and 18/18 token comparisons pass. The diagnostic maximum difference
is 0.00047084689140319824. This cannot identify the remaining cause or establish
performance equivalence. The standard runtime configuration stays unchanged.

The [generated model card](../registry/ocr-synthetic-frozen-001.json) retains source,
checkpoint, selection, original/robustness crop scores and complete export evidence
identities. `make register-ocr` actually regenerated these checks from the retained
run, including current training lineage and verified source pixels. The checkpoint
SHA-256 is `76acc813ae5ede18a27478396af7d34da83df5a19e1c41322a5ac4de2d926989`;
the ONNX artifact SHA-256 is
`7418100fef149c47029bf42f7be8b8e2a3c9480b3d33a560a4b8338b7c22a808`.
Complete evidence is in `.local/runs/ocr-synthetic-frozen-001` and the separate
`ocr-frozen-parity-diagnostic-20260926-s18-001` diagnostic directory.

The matching full-adaptation run remains active under the same dataset, seed,
width, batch and validation policy, at learning rate 1e-5 rather than 1e-4.
Training and file-ASR diagnosis overlap on the host, so no runtime-latency,
energy or thermal comparison is inferred. No human reference/crop approval,
final holdout, physical-device update or production model change occurs.

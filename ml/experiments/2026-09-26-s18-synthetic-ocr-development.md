# Pixel-verified synthetic-table OCR adaptation

The frozen-backbone experiment completes four epochs (1,024 optimizer steps) and
selects epoch one after three non-improving validation epochs. Its 91/91 exact
development crops improve the pretrained 90/91 by one whitespace difference in a
therapist line. The selected checkpoint adds no newly wrong critical validation
crop. This is not evidence of real-photo or complete-schedule improvement.

The prepared dataset has 512 training crops from 129 source groups and 91 validation
crops from 42 groups, all generated by the same table generator/font. Whole source
groups were assigned before crop selection; 2,435 validation crop occurrences with
identical training pixels were excluded. Validation retains 56 dates, 26 endings,
three starts and six therapist lines. It contains no novel title, room or notes
pixels and no real photographs. Dataset SHA-256:
`7314061c5104738dea1da2f627fea27fa30612372c4402968bfe700cce073ef6`.

The official Paddle export and ONNX conversion finish. On ONNX Runtime 1.22.0 CPU,
all 603 crops at widths 320 and 640 retain the same argmax sequence (1,206/1,206),
but only 1,188/1,206 satisfy rtol 1e-3 / atol 1e-5. Maximum absolute output difference
is 0.00047653913497924805. Numerical parity therefore fails; the newly trained
artifact is not allowed into the app probe or promoted to the runtime.

Disabling ORT graph optimization on the same 18 failed cases does not fix them:
0/18 numeric and 18/18 token comparisons pass. The diagnostic maximum difference
is 0.00047084689140319824. This cannot identify the remaining cause or establish
performance equivalence. The standard runtime configuration stays unchanged.

The [generated model card](../registry/ocr-synthetic-frozen-001.json) retains source,
checkpoint, selection, original/robustness crop scores and complete export evidence
identities. `make register-ocr` actually regenerated these checks from the retained
run, including current training lineage and verified source pixels. The checkpoint
SHA-256 is `76acc813ae5ede18a27478396af7d34da83df5a19e1c41322a5ac4de2d926989`;
the ONNX artifact SHA-256 is
`7418100fef149c47029bf42f7be8b8e2a3c9480b3d33a560a4b8338b7c22a808`.
Complete evidence is in `.local/runs/ocr-synthetic-frozen-001` and the separate
`ocr-frozen-parity-diagnostic-20260926-s18-001` diagnostic directory.

An independent diagnostic compares the original trainable pretrained checkpoint
with the pinned shipping ONNX recognizer on these same 1,206 inputs. It also fails
numeric parity: 1,187/1,206 pass, with 1,206/1,206 identical argmax sequences and
maximum absolute difference 0.0011280477046966553. This establishes that numerical
disagreement already exists in the baseline comparison; it does not establish its
cause or qualify either adapted model. Tolerances stay unchanged. The retained
report `.local/runs/ocr-pretrained-parity-20260926-s18-001/parity.json` has SHA-256
`e85a2a68662ade93457980c949267450cadef5b350f6dca5da376d41208929f2`.

The matching full-adaptation run completes five epochs (1,280 optimizer steps)
under the same dataset, seed, width, batch and validation policy, at learning rate
1e-5 rather than 1e-4. It selects epoch two with 91/91 exact validation crops and no
new critical errors. The final epoch declines to 70/91; the selected checkpoint
remains epoch two. The official export and ONNX conversion complete; numeric
parity passes 1,167/1,206 cases, while all 1,206 argmax sequences agree. Maximum
absolute difference is 0.000942528247833252. This candidate also fails deployment
parity. The full run's selected checkpoint SHA-256 is
`f2fb5c1fc0b0445414a33a787ebb9b1425c4dc88db9f10213e088a0b4251bb25`;
its report SHA-256 is
`5cc3cd232843a9c081288e890670d2a616e8e915b2b52d3434118a71e7259c41`.

The [combined generated model card](../registry/ocr-synthetic-development-001.json)
revalidates both completed runs and records failed parity for each. It has SHA-256
`231d713f7c140fa2368f8078f2f0a78d29350434b998b60e2640e8c40dbe0ead`.
Neither latest candidate enters the app probe. The earlier smoke experiment's
passing frozen artifact remains a separate, much smaller compatibility result.

The subsequent reproducible `diagnose-ocr-stage-parity` command isolates the failed
cases without changing weights, tolerances or runtime settings. The official
[export code](https://github.com/PaddlePaddle/PaddleOCR/blob/dab3fe35379033fdcb2d0e9572fac0b36c9a9ebf/ppocr/utils/export_model.py)
calls the backbone's reparameterization before saving the static graph. Applying
that same transformation to a copy of each selected model reproduces the saved
Paddle graph's outputs **bit-for-bit on all 18 frozen and 39 full failed cases**.
Thus these observed dynamic-to-static differences arise in reparameterization;
the separate static-Paddle-to-ONNX numerical differences remain unresolved.

| Failed-case subset | Dynamic → reparameterized | Reparameterized → saved Paddle | Saved Paddle → ONNX | Dynamic → ONNX |
| --- | --- | --- | --- | --- |
| Frozen, 18 cases | 10/18 numeric matches | 18/18, zero difference | 6/18 | 0/18 |
| Full, 39 cases | 14/39 numeric matches | 39/39, zero difference | 32/39 | 0/39 |

Every stage retains identical argmax sequences for these subsets. These selected
failures are not new independent examples or complete validation; they cannot
qualify either artifact. Diagnostic sources, selected run lineage, completed
export evidence and unchanged input hashes are verified. Reports under
`.local/runs/ocr-reparameterization-diagnostic-20260926-s18-001` have SHA-256:

- `frozen.json`: `142a8b94d8358ed71a4b77a6b85d46958211c13d36a7c6c14071963221181ffd`.
- `full.json`: `50c0a87b0f13cd6b21458919fefaf2c0bc2232e218ad8bd5bda4a9301bcfeeaa`.

A second diagnostic exports a copy of each same selected checkpoint **without**
calling `rep()`. The alternative saved Paddle graph exactly reproduces the
original dynamic outputs for all 57 previously failed cases. This removes the
observed dynamic/static discrepancy, but ONNX conversion/runtime still does not
meet the unchanged numeric gate:

| Failed-case subset | Dynamic → alternative saved Paddle | Dynamic → alternative ONNX, normal optimization | Dynamic → alternative ONNX, optimization disabled |
| --- | --- | --- | --- |
| Frozen, 18 cases | 18/18, zero difference | 4/18 | 4/18 |
| Full, 39 cases | 39/39, zero difference | 7/39 | 22/39 |

All alternative outputs retain the same argmax sequences. Maximum differences
for normal/disabled ONNX optimization are 0.0005781651/0.0004623532 (frozen) and
0.0009191632/0.0004197061 (full). These selected failures cannot estimate complete
parity: an alternative may also introduce differences in previously passing cases.
The unchanged source hashes and original four stage comparisons are retained in
each report. No threshold is relaxed or failed model card replaced.

The alternative frozen ONNX graph contains 68 Conv and 58 BatchNormalization
nodes versus the original graph's 57 and three, respectively; it retains the
separate branches. This is a diagnostic architecture, not a production speed or
resource improvement. Artifact SHA-256 values are
`4c6b321ba6306b2262c5f9176b54b326e056d8d5fa7011dbf1152d629e5f9e05`
(frozen) and `f12ee30bb2872bcb9d2303589d0a263531311795bcceb57e5258a9ecf41f2af8`
(full). Reports remain private:

- `.local/runs/ocr-unfused-frozen-diagnostic-20260926-s18-001/report.json`:
  `fa5c0939559c8e561b9a4843490b3a5be4ec860bd59e053bd152022dde9149fd`.
- `.local/runs/ocr-unfused-full-diagnostic-20260926-s18-001/report.json`:
  `26e5df1318b813cf905020f195e6172c63f714738f80b2a6cf29fe4acc751b9e`.

The [maintained diagnostic command](../training/ocr/README.md) requires a new
private export directory, retains conversion logs and verifies original and
alternative artifact hashes after inference. Existing directories are rejected.

Training and file-ASR diagnosis overlap on the host, so no runtime-latency,
energy or thermal comparison is inferred. No human reference/crop approval,
final holdout, physical-device update or production model change occurs.
